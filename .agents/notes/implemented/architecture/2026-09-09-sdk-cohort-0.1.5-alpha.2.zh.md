# Agent Note：SDK cohort 0.1.5-alpha.2

Status: implemented

## 问题

全家族停在 `0.1.2-rc.1` 稳定群体，而 npm 的 `alpha` 通道已推进到 `0.1.5-alpha.2`（全家族同步发布于 2026-09-09 14:25–14:30 UTC；仓库消费的全部 181 个 `dsh-*` 包齐备，cordis / cosmokit / schemastery 支持钉不变）。这一跳跨越整个 `0.1.3`/`0.1.4`/`0.1.5` 预发布序列，与之前的顺线小步不同，编译期与运行时词汇的断裂都在预期之内。本次升级必须在一个变更里移动全部群体面，并对每个被消费的增量给出分类。

## 决策

整个仓库在 `sdk/v0.1.5-alpha.2-cohort` 分支上锁定同一步调，整合前 rebase 到 `dev`：

- **依赖区间**：所有引用 `0.1.2-rc.1` 的 `@deepseek-ai/dsh-*` 区间改为对应的 `0.1.5-alpha.2`；精确钉保持精确（`shared` 的 client-ui-settings/slots、`desktop/runtime/host` → `@deepseek-ai/dsh@0.1.5-alpha.2`）。`@deepseek-ai/cordis` 保持 `^4.0.2`、cosmokit `1.8.3`、schemastery `3.18.2`、plugin-include `1.0.7`、plugin-loader `1.0.3`（支持钉不变；新宿主闭包在自己的树内把 cordis-plugin-hmr 抬到 `^1.0.17`、plugin-timer 抬到 `^1.1.4`）。
- **宿主底线，一份契约四个面**：每个家族包与 `scripts/plugin-template` 的 `dsh.engines.dsh >=0.1.5-alpha.2`、`README.md`/`README.en.md` 的静态 `DSH >=0.1.5--alpha.2` 徽章、`ci.yml`/`release.yml` 的 `npm install -g @deepseek-ai/dsh@0.1.5-alpha.2` 挂载钉、`docs/publish-prep.md` 的冒烟道句子。
- **发布时限策略**：两份 `minimumReleaseAgeExclude` 名单（根 57 行、desktop runtime 237 行，含 23 条的 `overrides:` 块）逐行对照 registry 复核——每个列名都有 alpha.2 版本——再整体平移到精确 alpha.2；pnpm 自动追加了根 3 行、desktop 17 行（rc.1 之后加入闭包的面：session-format 迁移链、侧栏 files/right 面板、http-proxy、tool-present、chunked-list 等）。五个上游停更的包（`dsh-client-runtime`、`dsh-client-schema-form`、`dsh-client-web-react`、`dsh-host-apiproxy`、`dsh-tool-subagent-report`）不在 alpha.2 闭包内，也不在任何名单里。
- **上游打包缺陷，缓解而非修补**：`dsh-client-store@0.1.5-alpha.2` 运行时仍导入 `zustand/vanilla`、`zustand/middleware`、`zustand/shallow` 与 `immer`，`dsh-client-ui-primitives@0.1.5-alpha.2` 仍导入 `anser`、`shiki`、`katex` 及 mdast/micromark 工具集，但两个发布清单都删掉了 rc.1 声明的这些依赖。用 `packageExtensions` 按 rc.1 钉为这两个精确版本补回；不改动任何已安装文件，宿主 web bundle 运行时自带副本。
- **流发布契约（唯一的源码断裂）**：持久会话日志退役 `assistant/chunk`；实时增量改为进程内 `agent/assistant-stream` 帧（`payload.agent` + `AssistantStreamFrame`），`assistant/message`/`assistant/attempt` 结算压缩后的流，且表面事件信封必填 `surfaceOp`。唯一消费方 `dsh-pet` 删除死亡的持久分支，新增 `projectAssistantStreamFrame`（reasoning-delta 保持 thinking、text-delta 转 review，碎碎念节奏不变），订阅该 scoped 发布并经 `payload.agent.session` 路由，spec harness 改喂帧与新信封字段。pet README 双语对更新投影词汇句。
- **新钉位踩出的潜在脚本 bug**：带多词 `DSH_CMD`（npx 钉版形式）运行 `scripts/e2e-mount.sh` 会走 CLI 回退分支，其中 `$DSH_CMD，` 未加花括号紧贴全角逗号；本机 bash 会把非 ASCII 字节并入变量名，`set -u` 直接中止。已改为 `${DSH_CMD}`。

对目标运行时的注入对齐以证据记录：workspace 的 `dsh.client.inject` 并集（12 个名字，由 `scripts/inject-contract.test.mjs` 钉住）与 alpha.2 `dsh-web-app` 组合行一致——其 patch 中缺席的两个名字（`dsh-client-store`、`dsh-client-ui-slots`）正是契约注释声明的平台表/静态模块行。

## 已否决的替代方案

- **等波次发完再动手**：首次 registry 扫描撞上发布中段（alpha tag 仍是 alpha.1）；几分钟后强制刷新的扫描确认已发齐，等待没有必要。
- **把 `dsh-better-sidebar` 升到 0.18.1**：其 peer 集与钉住的 0.18.0 完全相同（仍是 `^0.1.2-rc.1`）；没有随 cohort 移动精确钉的理由。`@mlgbnb/dsh-archive-manager` 维持排除（latest 1.0.10 未对 alpha.2 面集验证；恢复仍需行、依赖与挂载断言一起动）。
- **修补已安装 SDK 包的清单**解决打包缺陷：否决——`packageExtensions` 就是 pnpm 在解析层为此准备的机制，且保持 `node_modules` 原样。

## 测试

`pnpm typecheck`（22 包）、`pnpm build`、`pnpm test`（22 包；`packageExtensions` 落位前 client-store/primitives 的解析失败即上述上游缺陷，非回归）、`pnpm test:scripts`（family engines 不变量 + inject 契约）、`pnpm runtime-deps:check`、`pnpm aggregate:check`、`pnpm community:check`、`pnpm skin-center:check`、`pnpm docs:check`、`pnpm i18n:check` 全部通过。根 lockfile 通过 `pnpm install --frozen-lockfile --ignore-scripts`；desktop runtime lockfile 由真实 install 再生（其 frozen 复验被 win32 可选依赖的慢速拉取阻塞——解析本身由产出它的 install 证明）。worktree 构建的聚合包在真实 `@deepseek-ai/dsh@0.1.5-alpha.2` CLI（npx）下的 scratch profile 挂载并通过 `scripts/e2e-mount.sh` 无头渲染：bundle 注册进 `dsh.profile.bundles`，`dsh web` 以 tokenized 根 URL 启动，better-sidebar 在场、被排除的 archive-manager 缺席，Playwright lane 绿。自有 profile 上的托管 GUI 验收跟随用户侧宿主升级（见下）。

## 后果

engines 底线现在指名 `0.1.5-alpha.2`，正在运行的 `0.1.2-rc.1` 宿主无法加载本树安装的家族包：运行时上线保持用户侧且有序——先把宿主 CLI 升到 `0.1.5-alpha.2`（dsh-upgrade）、重启托管 `dsh web`，再做仓库 install/profile 刷新，并用 `profile-cohort-check.sh` 加一次工具调用冒烟重新接受每个本地 profile（模块身份分裂是此类失败形态，只回一条文本消息什么也证明不了）。两个 `packageExtensions` 块是上游缺陷欠账：npm 重新发布声明了自身运行时导入的 client-store/client-ui-primitives 后即可删除。`minimumReleaseAgeExclude` 随每次群体膨胀；desktop 载荷的 `overrides:` 块必须继续镜像新鲜官方闭包，rc.1 note 的探针-再-钉流程仍是标准做法。
