# Agent Note: SDK cohort 0.1.2-rc.1

Status: implemented

## Problem

The family tracks the official `@deepseek-ai` SDK cohort; since 2026-09-02 it sits on `0.1.2-alpha.4` while npm's `next` channel moved to `0.1.2-rc.1` (published 2026-09-03T06:21Z, the API-freeze candidate after alpha.5). Staying on an alpha line behind the freeze means the next host release will ship faces the family no longer compiles against, and the desktop app's bundled runtime would pin a pre-freeze host. The upgrade must move every cohort surface in one change and state exactly which host version the family now requires.

## Decision

The whole repository moves to the `0.1.2-rc.1` cohort in lockstep (commits `9958edbf` + `04c69e85`, rebased onto the desktop-launcher removal):

- **Dependency ranges**: every `@deepseek-ai/*` range referencing `0.1.2-alpha.4` becomes its rc.1 equivalent; exact pins stay exact (`shared` client-ui-settings/slots, `desktop/runtime/host` → `@deepseek-ai/dsh@0.1.2-rc.1`). `@deepseek-ai/cordis` stays `^4.0.2`, cosmokit `1.8.3`, schemastery `3.18.2` (unchanged support pins).
- **Host floor, one contract, four surfaces**: `dsh.engines.dsh >=0.1.2-rc.1` in every family package plus `scripts/plugin-template`, the static `DSH >=0.1.2-rc.1` badge in `README.md`/`README.en.md`, the `npm install -g @deepseek-ai/dsh@0.1.2-rc.1` mount pins in `ci.yml`/`release.yml`, and the smoke-lane sentence in `docs/publish-prep.md`. The floor names the cohort being installed.
- **Release-age policy**: rc.1 was inside pnpm 11's cooldown window at install time, so `minimumReleaseAgeExclude` swaps its alpha.4 exacts for the rc.1 exacts of the same package set (later upstream publishes get no bypass). The desktop runtime host additionally pins the rc.1 faces it resolved through an `overrides:` block (23 entries): pnpm 11.9's gate kept dropping those 23 to `0.1.2-alpha.4` even with the exclude list filled, while a fresh `npm install @deepseek-ai/dsh@0.1.2-rc.1` probe prefix proves the official closure is pure rc.1 — the overrides make the shipped desktop payload mirror the official closure instead of the gate's fallback. Its exclude list records both waves (191 auto-edit + 23 manual).
- **Surface-delta evidence**: declaration-level comparison of all 44 `@deepseek-ai` packages in the closure between the alpha.4 and rc.1 trees shows zero removed symbols, zero exports-map changes, and zero additions; workspace typecheck passes without source adaptation. rc.1 is a stabilization release for every face this repository consumes.
- **Rollout order**: the host CLI must be upgraded to rc.1 BEFORE the live `web` profile restarts against this tree; the engines floor names a host the old CLI cannot satisfy, and the linked profile resolves SDK peers from this checkout's `node_modules`.

## Testing

`pnpm typecheck`, `pnpm build`, `pnpm test` (incl. the real-host shell-isolation boot), `pnpm test:scripts` (family engines invariant), `aggregate:check`, `sync-shared:check`, `runtime-deps:check`, `docs:check`, `i18n:check`, `skin-center:check`, `community:check` all pass on the rebased branch; both lockfiles pass `pnpm install --frozen-lockfile --ignore-scripts`. The worktree-built aggregate mounts into a scratch profile under the rc.1 host binary and passes `scripts/e2e-mount.sh` headless rendering (better-sidebar present, excluded archive-manager absent). `profile-cohort-check.sh` reports all profiles symlinked to the host (no shadow-copy skew) pre-upgrade.

## Alternatives considered

- **Stay on alpha.4 / jump to alpha.5**: the user pinned rc.1; the alpha line continues at alpha.5 but the freeze is the rollout target.
- **Skip the desktop runtime pin** (leave the bundled host at alpha.4): would ship a desktop payload whose host generation differs from the repo cohort — the exact module-identity split the cohort discipline exists to prevent.
- **Hand-merge the lockfile across the rebase**: the desktop-launcher removal commit regenerated the root lockfile, so the conflicted file was resolved to the dev version and fully regenerated by `pnpm install` against the rebased manifests, then frozen-proven — never hand-edited.

## Consequences

- The family now requires a `>=0.1.2-rc.1` host; installing this tree on an older CLI fails the engines floor by design. The live profile flips only after the CLI upgrade and a `dsh web` restart (user-side; the shared checkout's `pnpm install` + `pnpm build` also wait for that restart so the running alpha.4 host keeps serving consistent bundles).
- The desktop runtime payload staging (`desktop/resources/runtime/`, git-ignored) still holds the alpha.4 build until someone runs `npm run prepare-runtime` in `desktop/`.
- Next cohort bump repeats the same mechanical moves; the desktop host project now carries both an exclude ledger and an overrides block that must move together.
