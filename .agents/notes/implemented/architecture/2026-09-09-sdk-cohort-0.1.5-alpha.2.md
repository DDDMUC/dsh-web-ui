# Agent Note: SDK cohort 0.1.5-alpha.2

Status: implemented

## Problem

The family sat on the `0.1.2-rc.1` stable cohort while npm's `alpha` channel moved to `0.1.5-alpha.2` (family-synchronized publish 2026-09-09 14:25–14:30 UTC; all 181 consumed `dsh-*` packages present, cordis / cosmokit / schemastery support pins unchanged). The jump spans the whole `0.1.3`/`0.1.4`/`0.1.5` prerelease sequence, so unlike the in-line bumps before it, compile-time and runtime vocabulary deltas were expected. The upgrade must move every cohort surface in one change and classify every consumed delta.

## Decision

The whole repository moves to the `0.1.5-alpha.2` cohort in lockstep on `sdk/v0.1.5-alpha.2-cohort`, rebased onto `dev` before integration:

- **Dependency ranges**: every `@deepseek-ai/dsh-*` range referencing `0.1.2-rc.1` becomes its `0.1.5-alpha.2` equivalent; exact pins stay exact (`shared` client-ui-settings/slots, `desktop/runtime/host` → `@deepseek-ai/dsh@0.1.5-alpha.2`). `@deepseek-ai/cordis` stays `^4.0.2`, cosmokit `1.8.3`, schemastery `3.18.2`, plugin-include `1.0.7`, plugin-loader `1.0.3` (unchanged support pins; the new host closure raises cordis-plugin-hmr to `^1.0.17` and plugin-timer to `^1.1.4` inside its own tree).
- **Host floor, one contract, four surfaces**: `dsh.engines.dsh >=0.1.5-alpha.2` in every family package plus `scripts/plugin-template`, the static `DSH >=0.1.5--alpha.2` badge in `README.md`/`README.en.md`, the `npm install -g @deepseek-ai/dsh@0.1.5-alpha.2` mount pins in `ci.yml`/`release.yml`, and the smoke-lane sentence in `docs/publish-prep.md`.
- **Release-age policy**: both `minimumReleaseAgeExclude` lists (root 57 rows, desktop runtime 237 rows including the 23-entry `overrides:` block) were re-verified row by row against the registry — every listed package has an alpha.2 release — and moved to the exact alpha.2 versions; pnpm auto-appended 3 root rows and 17 desktop rows for faces that joined the closure since rc.1 (session-format migration chain, sidebar files/right panels, http-proxy, tool-present, chunked-list, …). Five packages that stopped publishing upstream (`dsh-client-runtime`, `dsh-client-schema-form`, `dsh-client-web-react`, `dsh-host-apiproxy`, `dsh-tool-subagent-report`) are not part of the alpha.2 closure and appear in no list.
- **Upstream packaging defects, accommodation not repair**: `dsh-client-store@0.1.5-alpha.2` still runtime-imports `zustand/vanilla`, `zustand/middleware`, `zustand/shallow` and `immer`, and `dsh-client-ui-primitives@0.1.5-alpha.2` still imports `anser`, `shiki`, `katex` and the mdast/micromark utility set, but both published manifests dropped those dependencies from their rc.1 declarations. `packageExtensions` restores them at the rc.1 pins for exactly those two versions; no installed file is patched and the host web bundle supplies its own copies at runtime.
- **Stream-publication contract (the one source break)**: the durable session log retires `assistant/chunk`; live deltas publish as process-local `agent/assistant-stream` frames (`payload.agent` + `AssistantStreamFrame`), while `assistant/message`/`assistant/attempt` settle the compacted stream and surface-event envelopes now require `surfaceOp`. `dsh-pet` — the only consumer — drops the dead durable case, gains `projectAssistantStreamFrame` (reasoning-delta stays thinking, text-delta review, whisper cadence unchanged), subscribes the scoped publication routing through `payload.agent.session`, and its spec harness feeds frames plus the new envelope fields. The pet README pair updates the projected-vocabulary sentence.
- **Latent lane bug hit by the new pin**: running `scripts/e2e-mount.sh` with a multi-word `DSH_CMD` (the npx-pinned form) took the CLI-fallback branch, where `$DSH_CMD，` sits unbraced before a fullwidth comma; this bash folds the non-ASCII bytes into the name and `set -u` aborts. Braced as `${DSH_CMD}`.

Injection parity against the target runtime is recorded evidence: the workspace `dsh.client.inject` union (12 names, pinned by `scripts/inject-contract.test.mjs`) matches the alpha.2 `dsh-web-app` composition rows — the two names absent from its patch (`dsh-client-store`, `dsh-client-ui-slots`) are the contract's documented platform-table/static-module rows.

## Alternatives considered

- **Wait for the wave to finish publishing**: the first registry sweep caught the wave mid-rollout (alpha tag still `alpha.1`); a forced-refresh sweep minutes later confirmed full publication, so waiting was unnecessary.
- **Bump `dsh-better-sidebar` to 0.18.1**: its peer set is identical to the pinned 0.18.0 (still `^0.1.2-rc.1`); no cohort reason to move the exact pin. `@mlgbnb/dsh-archive-manager` stays excluded (latest 1.0.10 remains unverified against the alpha.2 face set; restore requires rows, deps and mount assertions together, as before).
- **Patch the installed SDK packages' manifests** for the two packaging defects: rejected — `packageExtensions` is pnpm's resolution-level mechanism for exactly this and keeps `node_modules` pristine.

## Testing

`pnpm typecheck` (22 packages), `pnpm build`, `pnpm test` (22 packages; the client-store/primitives resolution failures preceding the `packageExtensions` accommodation were the upstream defects above, not regressions), `pnpm test:scripts` (family engines invariant + inject contract), `pnpm runtime-deps:check`, `pnpm aggregate:check`, `pnpm community:check`, `pnpm skin-center:check`, `pnpm docs:check`, `pnpm i18n:check` all pass. Root lockfile passes `pnpm install --frozen-lockfile --ignore-scripts`; the desktop runtime lockfile is regenerated by a real install (its frozen re-verification was blocked on a slow win32 optional-dependency fetch — resolution itself is proven by the install that produced it). The worktree-built aggregate mounts into a scratch profile under the real `@deepseek-ai/dsh@0.1.5-alpha.2` CLI (npx) and passes `scripts/e2e-mount.sh` headless rendering: bundle registered in `dsh.profile.bundles`, `dsh web` boots with the tokenized root URL, better-sidebar present, excluded archive-manager absent, Playwright lane green. Managed-GUI acceptance on the user's own profile follows the user-side host upgrade (below).

## Consequences

The engines floor now names `0.1.5-alpha.2`, so the running `0.1.2-rc.1` host cannot load a family install from this tree: the runtime rollout stays user-side and ordered — upgrade the host CLI to `0.1.5-alpha.2` (dsh-upgrade), restart the managed `dsh web`, then run the repository install/profile refresh, and re-accept every local profile with `profile-cohort-check.sh` plus a tool-call smoke (module-identity splitting is the failure class, so a text reply alone proves nothing). The two `packageExtensions` blocks are upstream-defect debt: drop them when npm ships a client-store/client-ui-primitives that declares its runtime imports again. `minimumReleaseAgeExclude` grows with each cohort; the desktop payload's `overrides:` block must keep mirroring a fresh official closure, so the probe-then-pin pattern from the rc.1 note stays the procedure.
