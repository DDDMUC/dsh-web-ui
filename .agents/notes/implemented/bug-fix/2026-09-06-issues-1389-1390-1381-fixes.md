# Agent Note: Fixes for Issues #1389, #1390, and #1381

Status: implemented

## Problem

1. **Issue #1389**: In `packages/dsh-remote-web-ui/src/lan-bind.ts`, `writeLanBind` stripped managed blocks but did not strip a trailing empty list placeholder (`[]`). When toggling LAN access on a default profile whose `cordis.patch.yml` contained `[]`, the resulting YAML became `[]` followed immediately by a block list entry (`- id: webserver ...`), which is illegal YAML syntax and broke profile loading at startup.
2. **Issue #1390**: In `packages/dsh-remote-web-ui/src/client/index.ts`, `startMobileAdapt()` was invoked at the top-level module scope. When bundling the aggregate package (`@linxin666/dsh-web-all`), importing `client.js` immediately injected the floating whale button (`#dshRemoteWhale`) and portrait CSS into the DOM, even if `web-ui-remote-web-ui` was set to `disabled: true` in `cordis.patch.yml`.
3. **Issue #1381**: In `@linxin666/dsh-web-all`, previously removed plugins (`dsh-perf` and `desktop-launcher`) had their subpath exports removed from `package.json` by `scripts/aggregate.mjs`. Existing user profiles with stale patch entries referencing `@linxin666/dsh-web-all/dsh-perf` or `@linxin666/dsh-web-all/desktop-launcher` failed to boot with Node.js ESM error `ERR_PACKAGE_PATH_NOT_EXPORTED`.

## Decision

1. **Issue #1389**: In `writeLanBind`, strip any trailing `[]` placeholder from `base` (`rawBase.replace(/\[\s*\]\s*$/, '').trimEnd()`) before prepending it to the managed block.
2. **Issue #1390**: Remove the top-level `startMobileAdapt()` call from `packages/dsh-remote-web-ui/src/client/index.ts`. Move invocation inside `apply(ctx)` and register a cleanup hook with `ctx.effect(() => () => { window.__dshRemoteAdapt?.setEnabled(false) })` to ensure the DOM is only touched when the plugin is active.
3. **Issue #1381**:
   - Add `tombstones:` support to `packages/dsh-web-all/aggregate.yml` and `scripts/aggregate.mjs` to preserve exports for retired subpaths (`./desktop-launcher` and `./dsh-perf`) pointing to `./lib/shells/shell.js`.
   - In `packages/dsh-web-all/src/shell.ts`, recognize `RETIRED_PLUGINS` (`@linxin666/dsh-perf`, `@linxin666/dsh-desktop-launcher`) and mount them as quiet no-ops without throwing or degrading.
   - Regenerate `packages/dsh-web-all/package.json` with `node scripts/aggregate.mjs`.

## Alternatives considered

- **Requiring manual profile cleanup by users**: rejected. Users expect updates via `dsh plugin add @linxin666/dsh-web-all@latest` to be backwards-compatible; failing to boot with unexported subpaths creates hard breakages.
- **Keeping startMobileAdapt at module scope with an immediate DOM probe**: rejected. Cordis lifecycle gating should govern plugin behavior; `apply(ctx)` is the correct lifecycle hook for browser features.

## Consequences

- Enabling LAN access on clean profiles with `[]` produces valid YAML.
- Disabling `web-ui-remote-web-ui` in `cordis.patch.yml` completely disables mobile DOM injections and gesture interceptors.
- Existing profiles retaining legacy `dsh-perf` or `desktop-launcher` rows boot cleanly on `dsh-web-all` v0.3.16+.
