# Agent Note: multi-issue landing for #1368, #1370, #1372, and #1359

Status: implemented

## Problem

Four issues were reported across skins, settings, aggregate mounting, and task-board plugins:

1. **#1368 (maid-atelier & phoebe-atelier composer overlaps SettingsPanel)**: In both themes, the bottom composer container and seat kept higher stacking contexts and sticky positioning, overlapping the Settings dialog and sidebar footer in responsive and pinned viewports.
2. **#1370 (settings cards show unexposed config namespaces)**: The Web Plugins settings page showed "unexposed configuration namespace" cards because namespace allowlist matching dropped canonical aliases (`dsh-market` vs `dsh-web-ui-market`, and official `dshmarket`), and plugins registered via legacy `settings.section` lacked safety guards against older host versions.
3. **#1372 (hidden UI entry points for disabled sub-plugins in aggregate bundle)**: In the aggregate `dsh-web-all` bundle, disabled or deleted sub-plugin rows in `cordis.patch.yml` still mounted their client-side UI buttons and entry points because the client loader mounted all bundled children indiscriminately.
4. **#1359 (per-task model pinning in task-board)**: Tasks could specify workspaces, presets, and permissions, but could not pin a specific LLM model, requiring users to manually re-select models in host sessions.

## Decision

Resolved all four issues in a unified release-readiness pass:

- **Skins (#1368)**: Relaxed selector matching in `maid-atelier/patches.css` and `phoebe-atelier/skin.css`. When settings dialogs are open (`body[data-maid-settings-open]` or `body[data-phoebe-settings-open]`), force `:is([data-composer-seat], [data-slot="conversation.composer"], [data-composer-card])` to `z-index: 0 !important` and set sidebar container stacking to `z-index: auto !important`, fully clearing dialog interactions.
- **Settings allowlist and fallback (#1370)**: Expanded `FAMILY_NAMESPACES` in `dsh-web-settings` with all ecosystem namespaces (`dsh-market`, `usage`, `doctor`, `liangshen`, `session-archive`). Enhanced `resolveNamespaceEntries` to bi-directionally map equivalent names and official aliases. Wrapped `ctx.get('settings.section')?.installSection` in all plugin entrypoints with graceful fallbacks for older hosts.
- **Aggregate child gating (#1372)**: Updated `dsh-web-all` client mounting logic with `CHILD_ROW_IDS` and `activeBootEntryIds()`. When `__DSH_BOOT__.entries` is available, each child plugin checks if its row id is active, skipping client mounting if disabled or removed.
- **Task-board model pinning (#1359)**: Extended task schema, update patch, and protocol with optional `model?: string` field. Connected `session.selectModel` in `HostExecutionRunner` during session launch, and added model picker UI in `NewTaskModal` and `TaskDetail` components.
- **Market sync and CI workflow hygiene**: Regenerated committed market site artifacts to sync maid-atelier and phoebe-atelier skin changes; updated desktop release workflow to resolve shellcheck SC2035.

## Alternatives considered

- **Per-skin manual dialog re-layering via javascript hooks (#1368)**: Rejected because pure declarative CSS rules handle stacking cleanly without hook lifecycle overhead or DOM mutation delays.
- **Strict single-string namespace equality in settings (#1370)**: Rejected because ecosystem naming has legacy variants and official host differences; an alias-expansion resolver is more robust and backward-compatible.
- **Splitting aggregate bundles into individual dynamic imports (#1372)**: Rejected because the bundle structure is designed as a single self-contained artifact for performance; checking boot entries achieves exact gating without architecture refactoring.
- **Enforcing model selection at global workspace level only (#1359)**: Rejected because different automated tasks naturally require different model capabilities (e.g. reasoning vs quick coding).

## Consequences

- Settings panel is accessible and clickable in all states across maid-atelier and phoebe-atelier skins.
- Web plugin settings cards reliably resolve configuration namespaces without misleading warnings.
- Disabling an aggregate child row in `cordis.patch.yml` cleanly suppresses its client UI.
- Task-board users can configure per-task models that are automatically pinned during execution.
