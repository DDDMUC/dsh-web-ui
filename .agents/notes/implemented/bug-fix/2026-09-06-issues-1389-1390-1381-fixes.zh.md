# Agent Note: Issue #1389、#1390 与 #1381 修复

Status: implemented

## 问题

1. **Issue #1389**: 在 `packages/dsh-remote-web-ui/src/lan-bind.ts` 中，`writeLanBind` 剥离受管配置块后未剥离末尾的空数组占位符（`[]`）。在默认包含 `[]` 的 profile 上开启局域网访问时，生成的 YAML 出现 `[]` 后直接紧跟列表项（`- id: webserver ...`），破坏了 YAML 语法，导致启动时 profile 解析失败。
2. **Issue #1390**: 在 `packages/dsh-remote-web-ui/src/client/index.ts` 中，`startMobileAdapt()` 在模块顶层作用域被直接调用。在全家桶（`@linxin666/dsh-web-all`）聚合打包后，只要加载了 `client.js`，悬浮小鲸鱼按钮（`#dshRemoteWhale`）和移动端竖屏样式就会立即注入 DOM，即使用户在 `cordis.patch.yml` 中配置了 `web-ui-remote-web-ui` 的 `disabled: true` 也无法阻止其生效。
3. **Issue #1381**: 在 `@linxin666/dsh-web-all` 中，此前移除的插件（`dsh-perf` 和 `desktop-launcher`）被 `scripts/aggregate.mjs` 从 `package.json` 的 `exports` 中删除了。老用户的 profile 中若残留对 `@linxin666/dsh-web-all/dsh-perf` 或 `@linxin666/dsh-web-all/desktop-launcher` 的条目引用，会在启动时抛出 Node.js ESM 错误 `ERR_PACKAGE_PATH_NOT_EXPORTED` 并导致启动崩溃。

## 决策

1. **Issue #1389**: 在 `writeLanBind` 中，向受管配置块拼接前从 `base` 末尾剥除空数组占位符 `[]`（`rawBase.replace(/\[\s*\]\s*$/, '').trimEnd()`）。
2. **Issue #1390**: 移除 `packages/dsh-remote-web-ui/src/client/index.ts` 顶层的 `startMobileAdapt()` 调用。将其移入 `apply(ctx)` 函数体内，并通过 `ctx.effect(() => () => { window.__dshRemoteAdapt?.setEnabled(false) })` 注册卸载时的清理逻辑，确保插件在被禁用时不产生任何 DOM 注入。
3. **Issue #1381**:
   - 在 `packages/dsh-web-all/aggregate.yml` 与 `scripts/aggregate.mjs` 中增加 `tombstones:` 机制，为退役子路径（`./desktop-launcher` 与 `./dsh-perf`）保留指向 `./lib/shells/shell.js` 的导出。
   - 在 `packages/dsh-web-all/src/shell.ts` 中识别 `RETIRED_PLUGINS`（`@linxin666/dsh-perf`、`@linxin666/dsh-desktop-launcher`），将其直接作为静默 no-op 挂载，不触发异常或降级记录。
   - 执行 `node scripts/aggregate.mjs` 重新生成 `packages/dsh-web-all/package.json`。

## 备选方案

- **要求用户手动清理旧 Profile**: 拒绝。用户通过 `dsh plugin add @linxin666/dsh-web-all@latest` 更新时预期向后兼容；因缺少导出导致启动崩溃属于破坏性体验。
- **保持 startMobileAdapt 在模块顶层并增加运行时探测**: 拒绝。插件功能应当完全受 Cordis 生命周期管控，`apply(ctx)` 是浏览器端功能的正规入口。

## 影响

- 默认带有 `[]` 的干净 profile 在开启局域网访问后生成合法的 YAML 配置。
- 在 `cordis.patch.yml` 中将 `web-ui-remote-web-ui` 设为 `disabled: true` 时，前端不会注入小鲸鱼按钮或接管移动端手势。
- 保留旧版 `dsh-perf` 或 `desktop-launcher` 配置的老用户升级至 `dsh-web-all` v0.3.16+ 能够平稳启动。
