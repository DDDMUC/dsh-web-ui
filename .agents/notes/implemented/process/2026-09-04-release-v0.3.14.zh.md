# Agent Note: v0.3.14 发布

状态：已实施

## 问题

全家桶需要下一次统一发版，覆盖 `v0.3.13..dev` 区间：`0.1.2-rc.1` SDK cohort 整体迁移（全部 cohort 面同步移动、宿主下限在四个面上抬高、桌面运行时宿主的 overrides 钉扎）、桌面故事整合（完全移除 dsh-desktop-launcher 插件，加上新的 Electron 桌面应用骨架——内置运行时及其预留端口宿主修复）、dsh-doctor 监护进程改为宿主有界子进程、聚合包将 dsh-better-sidebar 升级到 0.18.0、skin-center 壁纸分页与内容分级筛选、blue-fantasy 根级 backdrop-filter 移除、dsh-annotation npm 坐标修复，以及 liangshen 对 SDK 会话事件破坏性变更的适配。

## 决策

按标准统一版本流程发布 v0.3.14（0.3.13 的下一个补丁版本）；用户未指定版本号，适用默认下一补丁规则。兼容性审计将本区间判定为可安全自动升级，其中两处有意的行为变更归类为兼容：

- desktop-launcher 移除在聚合路径上无需迁移：用户 profile 引用的是 `@linxin666/dsh-web-all`，其补丁不再挂载启动器；即使残留仅解析器层面的 profile 依赖，没有补丁行就不会挂载任何东西，并会在下一次 profile 修复中被清理。npm 包名以 0.3.13 退役（不下架），已生成的桌面图标继续可用，因为其脚本直接 shell 出 `dsh` 命令。
- dsh-doctor 监护进程变携带确定性的自动迁移：新代码首次启动会移除旧的登录持久化服务注册；`service-install`/`service-plan` 动词移除，`service-uninstall` 保留用于手动清理。无双挂载或孤儿风险：有界子进程随孵化宿主一同停止（`--parent-pid` 监视），并经真机验证。
- rc.1 宿主下限是设计内的 cohort 门禁而非意外破坏：全部 20 个家族包加模板声明 `dsh.engines.dsh >=0.1.2-rc.1`，另有 README 徽章、`npm install -g @deepseek-ai/dsh@0.1.2-rc.1` 的 CI/release 挂载钉扎、以及 publish-prep 冒烟语句。对 44 个 face 闭包的声明级比对为零表面差异，旧宿主会显式卡在下限检查上，而不是带着不兼容启动。
- 本仓库 authored 的其余持久化标识符全部冻结：设置 section id、API 路径、存储键、线协议形状与 market-worker 面在该区间均未变化；annotation 坐标修复只是 `community.json` 数据加再生的 Workshop 清单。

验证证据：bump 前在 dev 上全套门禁通过（`sync-shared:check`、`typecheck`、`test` 共 3953 项测试全部通过且零失败、`test:scripts`、`runtime-deps:check`、`aggregate:check`、`market:check`、`skin-center:check`、`docs:check`、`i18n:check`、`community:check`），全部 20 个家族包版本 bump 到 0.3.14，bundle 与市场资产基于同一次 bump 重建并一起提交（三个入库的 `lib/client.js` 差异仅为版本字符串；market dist 不含版本字符串，`market:check` 通过）。bump 提交 `a3219001` 落在 `dev`，`main` 快进到该提交，tag 从 `main` 打出。发布管线（run 33816812001）端到端成功，包括带门控的 npm 发布、挂载冒烟、以及基于入库双语 notes 创建的 GitHub Release。发布后验证确认 `@linxin666/dsh-web-all`、`@linxin666/dsh-client-ui-skin-center`、`@linxin666/dsh-client-ui-market` 在 registry 上均为 0.3.14；旧包 `@linxin666/dsh-web-ui-all` 保持在 0.3.6 且弃用元数据完好。

## 已考虑的替代方案

- 用 minor 版本标记桌面应用与 rc.1 cohort：否决——家族约定是统一的每发布一补丁节奏；cohort 是零消费面差异的稳定化发布，应用骨架是纯新增。
- 推迟发布直到桌面应用带签名安装包：否决——签名、公证与打包是桌面笔记中记录的既定后续项；cohort 迁移不应等待它们。

## 后果

- npm `@linxin666/*` 全家桶进入 0.3.14；旧聚合包保持 0.3.6 弃用状态，管线的旧包双发步骤继续为空操作。
- `dev` 与 `main` 都停在 `a3219001`，无残留分叉。
- 早于 0.1.2-rc.1 的宿主按设计卡在 engines 下限上；恢复顺序是先升级宿主 CLI，再更新插件，再重启。更新后 desktop-launcher 设置卡与悬浮电源按钮消失，直到 Electron 桌面应用发布；doctor 的登录持久化守护进程在新代码首次启动时消失，宿主无法启动时以 `dsh-doctor diagnose / repair` 作为手动路径。
- 本发布只交付代码：按 cohort 上线顺序，live profile 将在用户侧完成宿主 CLI 升级与 `dsh web` 重启后切换到 rc.1 cohort。
