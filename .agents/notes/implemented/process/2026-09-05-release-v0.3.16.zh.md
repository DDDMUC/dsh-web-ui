# Agent Note：发布 v0.3.16

Status: implemented

## 问题

全家桶需要覆盖 `v0.3.15..dev` 区间的下一次统一发版。该区间只有一个功能性改动：修复 v0.3.15 的严重回归——聚合包子插件挂载门控误读了启动载荷的线协议（启动条目只携带客户端 bundle 的包 id，没有补丁行 id，也没有 `name`/`disabled` 字段），导致每次聚合安装后门控跳过全部家族子插件，整个 dsh-web 插件家族的设置界面从设置对话框中消失。

## 决策

按标准统一版本流程发布 v0.3.16（0.3.15 的下一个补丁版本）；用户未指定版本号，适用默认下一补丁规则。审计将该区间归类为无迁移面的向后兼容修复：

- 该改动把 `@linxin666/dsh-web-all` 客户端的挂载语义恢复为 0.3.15 之前的双挂载防护语义：仅当子插件的包 id 出现在宿主下发的启动图中才跳过，否则挂载。包身份、被其他包消费的导出（`CHILD_ROW_IDS` 是 v0.3.15 新增的导出，随伪造损坏载荷形状的测试一并移除）、profile 写入、持久化键与线协议契约均未变化，或恢复为长期在线的形状。
- Issue #1372（隐藏已禁用家族行的 UI 入口）随本次回退而失效并保持开放，待宿主提供真实的行状态信号后再实现；release notes 已明确写出。
- 区间内没有 `@deepseek-ai/*` cohort 或引擎下限变化。

验证证据：bump 前 dev 上全部门禁通过（`sync-shared:check`、`typecheck`、`test`、`test:scripts`、`runtime-deps:check`、`aggregate:check`（18 行 / 17 依赖 / 14 客户端子项）、`market:check`、`skin-center:check`、`docs:check`、`i18n:check`），全部家族包版本 bump 到 0.3.16，bundle 与市场资产由同一次 bump 重建并一起提交（重建后 `market:check` 通过），双语 release notes 以 `docs/release-notes/v0.3.16.md` 随发版提交入库。发版提交落在 `dev`，`main` 快进到该提交，tag 从 `main` 打出。

## 曾考虑的替代方案

- 按 skill 片段把发版提交直接落在 `main` 上：否决——`packages/dsh-web-all/lib/client.js` 在 `main` 与 `dev` 之间不同（修复提交），带着未提交的重建产物跨分支切换很脆弱；在 `dev` 上提交再快进 `main` 得到完全相同的历史，也与 v0.3.15 的实践一致。
- 在本版本里顺手实现 #1372 的正规行状态信号：修复 note 中已否决——那是新的宿主-客户端契约，不是热修；先恢复服务。

## 后果

- npm `@linxin666/*` 全家桶 19 个包进入 0.3.16；旧聚合包保持弃用状态停在 0.3.6，管线的旧包双发步骤保持 no-op。
- 聚合安装重新挂载全部家族 UI；在 #1372 以真实行状态信号落地之前，禁用家族行后其 UI 入口仍可见。
- v0.3.16 的桌面安装包由 `desktop-release.yml` 在 tag 推送后自动构建并上传到 GitHub Release。
