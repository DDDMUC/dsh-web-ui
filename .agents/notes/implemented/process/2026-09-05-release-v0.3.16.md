# Agent Note: Release v0.3.16

Status: implemented

## Problem

The family needed its next unified release covering the `v0.3.15..dev` range. The range holds exactly one functional change: the fix for the critical v0.3.15 regression where the aggregate child-mount gate misread the boot payload wire shape (boot entries carry client-bundle package ids only — no patch row ids, no `name`/`disabled`), so on every aggregate install the gate skipped every family child and the whole dsh-web plugin family UI vanished from the settings dialog.

## Decision

Release v0.3.16 (next patch after 0.3.15) by the standard unified-version flow; the user specified no version, so the default next-patch rule applied. The audit closed the range as a backward-compatible fix with no migration surface:

- The change restores the pre-0.3.15 double-mount semantics in `@linxin666/dsh-web-all`'s client: skip a child only when its package id appears in the served boot graph, otherwise mount it. Package identities, exports consumed by other packages (`CHILD_ROW_IDS` was a v0.3.15-only export removed together with the tests that fabricated the broken payload shape), profile writes, persisted keys, and wire contracts are unchanged or revert to long-shipped shapes.
- Issue #1372 (hide UI entry points of disabled family rows) is effectively reverted and stays open until the host provides a real row-state signal; the release notes state this explicitly.
- No `@deepseek-ai/*` cohort or engine-floor changes in the range.

Validation evidence: the full gate set green on dev before the bump (`sync-shared:check`, `typecheck`, `test`, `test:scripts`, `runtime-deps:check`, `aggregate:check` at 18 rows / 17 deps / 14 client children, `market:check`, `skin-center:check`, `docs:check`, `i18n:check`), all family package versions bumped to 0.3.16, bundles and market assets rebuilt from the same bump and committed together (`market:check` passed after the rebuild), bilingual release notes committed as `docs/release-notes/v0.3.16.md`. The release commit lands on `dev`, `main` fast-forwards to it, and the tag is cut from `main`.

Incident and recovery (run 33941466247): the gated npm publish job succeeded, but the Mount + headless-render smoke failed seconds later — the e2e-mount rewrite step saw most family packages at 0.3.16 while `@linxin666/dsh-client-ui-community-plugins@0.3.16` and two others were still propagating, and pnpm's fetch of the aggregate dependency hit a registry edge still serving 0.3.15 as latest (`ERR_PNPM_NO_MATCHING_VERSION`). A publish-to-smoke registry propagation race, not a packaging defect. Recovery followed the no-tag-repush rule: confirmed all 19 packages at 0.3.16 on the registry (legacy aggregate untouched at 0.3.6, deprecation intact), then `gh run rerun --failed` re-executed only the Mount smoke + GitHub Release job (1m45s, green; the succeeded publish job was not re-run, so no version was published twice). The GitHub Release was created from the committed bilingual notes; body diff against `docs/release-notes/v0.3.16.md` matches (trailing-newline normalization only) and `user-mention` count is 0. Mid-flight, a second session committed the family row-state route proposal (`2af80237`) onto dev between the fix and the bump; the notes were corrected in a follow-up commit (`ae035ca4`, the tagged HEAD) so the release range is fully covered.

## Alternatives considered

- Landing the release commit directly on `main` as the skill snippet sketches: rejected — `packages/dsh-web-all/lib/client.js` differs between `main` and `dev` (the fix commit), so carrying the uncommitted rebuild across a branch switch is fragile; committing on `dev` and fast-forwarding `main` reaches the identical history and matches the v0.3.15 practice.
- Reimplementing the proper #1372 row-state signal in this release: rejected in the fix note — it is a new host-client contract, not a hotfix; restore service first.

## Consequences

- npm `@linxin666/*` moves to 0.3.16 across the 19-package family; the legacy aggregate stays deprecated at 0.3.6 and the pipeline's legacy dual-publish step remains a no-op.
- Aggregate installs mount their family UIs again; disabling a family row leaves its UI entry visible until #1372 lands on a real row-state signal.
- Desktop installers for v0.3.16 are built and uploaded to the GitHub Release by `desktop-release.yml` on the tag push.
