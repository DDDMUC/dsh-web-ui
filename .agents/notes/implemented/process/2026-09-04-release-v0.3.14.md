# Agent Note: Release v0.3.14

Status: implemented

## Problem

The family needed its next unified release covering the `v0.3.13..dev` range: the `0.1.2-rc.1` SDK cohort move (all cohort surfaces in lockstep, host floor raised on four surfaces, desktop runtime host overrides pin), the desktop-story consolidation (complete removal of the dsh-desktop-launcher plugin plus the new Electron desktop app skeleton with a bundled runtime and its reserved-port host fix), the dsh-doctor supervisor reshaped into a host-bounded child process, the aggregate bump of dsh-better-sidebar to 0.18.0, the skin-center wallpaper pagination and content rating filter, the blue-fantasy root backdrop-filter removal, the dsh-annotation npm coordinate fix, and the liangshen adaptation to the SDK session-events breaking changes.

## Decision

Release v0.3.14 (next patch after 0.3.13) by the standard unified-version flow; the user specified no version, so the default next-patch rule applied. The audit closed the range as safe for automatic upgrade, with two intentional behavior changes classified as compatible:

- The desktop-launcher removal needs no migration on the aggregate path: user profiles reference `@linxin666/dsh-web-all`, whose patch no longer mounts the launcher; a stale resolver-only profile dependency, if any, mounts nothing without a patch row and is pruned by the next profile heal. The npm name is retired at 0.3.13 (not unpublished), and desktop icons already generated keep working because their scripts shell out to `dsh` directly.
- The dsh-doctor supervisor change carries a deterministic automatic migration: the first boot of the new code removes the legacy login-persistent service registration, and the `service-install`/`service-plan` verbs are gone while `service-uninstall` remains for manual cleanup. No double-mount or orphan risk: the bounded child stops with its spawning host (`--parent-pid` watch), verified live.
- The rc.1 host floor is the designed cohort gate, not an accidental break: `dsh.engines.dsh >=0.1.2-rc.1` across all 20 family packages plus the template, the README badge, the `npm install -g @deepseek-ai/dsh@0.1.2-rc.1` CI/release mount pins, and the publish-prep smoke sentence. The declaration-level comparison of the 44-face closure showed zero surface delta, so older hosts fail the floor explicitly instead of booting into incompatibility.
- All persisted identifiers authored by this repository are otherwise frozen: settings section ids, API paths, storage keys, wire shapes, and the market-worker surface are unchanged in this range; the annotation coordinate fix is data-only in `community.json` plus the regenerated Workshop manifest.

Validation evidence: the full gate set green on dev before the bump (`sync-shared:check`, `typecheck`, `test` with 3953 tests passing and none failing, `test:scripts`, `runtime-deps:check`, `aggregate:check`, `market:check`, `skin-center:check`, `docs:check`, `i18n:check`, `community:check`), all 20 family package versions bumped to 0.3.14, bundles and market assets rebuilt from the same bump and committed together (the three tracked `lib/client.js` diffs are version-string-only; market dist carries no version strings, and `market:check` passed). The bump commit `a3219001` landed on `dev`, `main` fast-forwarded to it, and the tag was cut from `main`. The release pipeline (run 33816812001) succeeded end to end including the gated npm publish, the mount smoke, and the GitHub Release created from the committed bilingual notes. Post-release verification confirmed 0.3.14 on the registry for `@linxin666/dsh-web-all`, `@linxin666/dsh-client-ui-skin-center`, and `@linxin666/dsh-client-ui-market`; the legacy `@linxin666/dsh-web-ui-all` stays at 0.3.6 with its deprecation metadata intact.

## Alternatives considered

- A minor bump to mark the desktop app and the rc.1 cohort: rejected — the family convention is a unified patch-per-release cadence; the cohort is a stabilization release with zero consumed-surface delta and the app skeleton is additive.
- Holding the release until the desktop app ships signed installers: rejected — signing, notarization, and packaging are deliberate follow-ups recorded in the desktop notes; the cohort move should not wait on them.

## Consequences

- npm `@linxin666/*` moves to 0.3.14 across the family; the legacy aggregate stays deprecated at 0.3.6 and the pipeline's legacy dual-publish step remains a no-op.
- `dev` and `main` both sit at `a3219001` with no residual split.
- Users on hosts older than 0.1.2-rc.1 fail the engines floor by design; the recovery order is host CLI upgrade first, then plugin update, then restart. The desktop-launcher settings card and floating power button disappear after the update until the Electron desktop app ships; the doctor login-persistent daemon disappears on first boot of the new code, with `dsh-doctor diagnose / repair` as the manual path for an unbootable host.
- This release ships code only: the live profile flips to the rc.1 cohort after the user-side host CLI upgrade and `dsh web` restart, per the cohort rollout order.
