# Agent Note: Release v0.3.15

Status: implemented

## Problem

The family needed its next unified release covering the `v0.3.14..dev` range: the complete removal of the built-in dsh-perf plugin (the range's one breaking change), the remote-web-ui pairing story for docker/reverse-proxy setups via token and trusted hosts plus its hardening fixes (bounded trusted-host table, loopback proxy teardown of both legs, dead lanAddresses dep), the dsh-web-all degraded-route ref-counted singleton fix, the four-issue fix batch (#1368, #1370, #1372, #1359) across skins/settings/web-all/task-board, the new blue-throated-bee-eater skin, the maid-atelier and phoebe-atelier skin CSS fixes, the pet plugin performance and teardown fixes, the desktop installer wizard with VC runtime check and uninstall prompt plus the desktop-release packaging workflow, the dsh-audiogen community-index registration, and the release-notes mention-neutralization fix.

## Decision

Release v0.3.15 (next patch after 0.3.14) by the standard unified-version flow; the user specified no version, so the default next-patch rule applied. The audit closed the range as safe for automatic upgrade:

- The dsh-perf removal follows the production-proven dsh-aionui-panel removal pattern (shipped in v0.3.7 and exercised by five releases since): aggregate installs reference `@linxin666/dsh-web-all`, whose regenerated patch no longer mounts dsh-perf, so the update re-renders profile rows and drops the plugin; the `session-persistence-jsonl` tuning patch falls back to the stock harness row with no user action. Standalone dsh-perf installs keep working but are frozen — documented in the release notes with the no-further-releases statement. The registry package stays published and the market badge allowlist keeps `@linxin666/dsh-perf` so download totals are unchanged.
- The task-board `model` field is a same-bundle optional wire extension: client and host ship in one plugin bundle, the validator accepts old payloads without the field, and persisted tasks without `model` stay valid. The settings allowlist change maps `market` to both the `dsh-market` and `dsh-web-ui-market` namespaces (a superset of the old resolution, backward compatible). The remote-web-ui token/trusted-host options are additive config surface. All other persisted identifiers are frozen in this range.
- Package identities, exports, and `dsh.engines.dsh` floors are unchanged; the family count is 19 packages after the dsh-perf directory deletion.

Validation evidence: the full gate set green on dev before the bump (`sync-shared:check`, `typecheck`, `test`, `test:scripts`, `runtime-deps:check`, `aggregate:check` at 18 rows / 17 deps / 14 client children, `market:check`, `skin-center:check`, `docs:check`, `i18n:check`), all 19 family package versions bumped to 0.3.15, bundles and market assets rebuilt from the same bump and committed together (`market:check` passed after the rebuild). The release commit `d7ba130a` landed on `dev`, `main` fast-forwarded to it, and the tag was cut from `main`. The release pipeline (run 33932764652) succeeded end to end in 5m47s including the gated npm publish, the mount + headless-render smoke, and the GitHub Release created from the committed bilingual notes. The desktop-release workflow (run 33932764740) fired on the same tag. Post-release verification: 0.3.15 on the registry for `@linxin666/dsh-web-all` and `@linxin666/dsh-client-ui-skin-center`; the legacy `@linxin666/dsh-web-ui-all` stays at 0.3.6 with deprecation metadata intact; the release body renders with `user-mention` count 0 and the remote tag points at `d7ba130a`.

## Alternatives considered

- A minor bump to mark the dsh-perf removal: rejected — the family convention is a unified patch-per-release cadence, and the removal is a simplification with a deterministic aggregate-path migration, not a feature line.
- Keeping dsh-perf installable but out of the aggregate: already rejected in the removal note — an orphaned package keeps every maintenance cost with no user reachable from a default install.

## Consequences

- npm `@linxin666/*` moves to 0.3.15 across the 19-package family; the legacy aggregate stays deprecated at 0.3.6 and the pipeline's legacy dual-publish step remains a no-op.
- `dev` and `main` both sit at `d7ba130a` with no residual split.
- Every install loses the performance HUD, the attribution scoreboard, render degrade, and the write-batch tuning; sessions are served by the stock `session-persistence-jsonl` harness row. Users who mounted dsh-perf standalone keep their install but receive no updates.
- Desktop installers for v0.3.15 are built and uploaded to the GitHub Release by `desktop-release.yml` on the tag push; the first tag-driven desktop packaging run is run 33932764740.
