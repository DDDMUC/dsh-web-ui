# Agent Note: 把粘贴文本用 AI 解析进新建任务表单

Status: proposed

## Problem

issue #1540 希望看板能把粘贴进来的文本（例如从聊天软件复制的一段对话）变成任务：提炼并归类内容，在新建任务时预填标题、描述和执行 Prompt。

## Proposal

在任务看板新增一条 Host 路由（`POST {prefix}/parse`），挂在既有的回环与同源围栏之后，接收原始文本并返回结构化的任务字段；新建任务弹窗增加一个粘贴框和解析按钮，返回的字段先回填进表单、由用户确认后再创建。模型调用走 `llm` 服务，路由由部署选定；失败时返回带类型的错误（未配置模型、回复无法解析），而不是原始报错。解析时会去掉代码围栏并读取第一个 JSON 对象；解析失败时把原文作为执行 Prompt 提供出去，而不是丢弃。

## Context & Efficiency Impact

多一条 Host 路由和一个弹窗区块。解析草稿不写进账本，只有用户接受的字段会落盘。模型调用花的是部署自己的额度，而且可能超过传输层默认的 15 秒超时，因此需要单独的 30-45 秒预算、取消入口和可见的等待状态。

## Alternatives considered

在浏览器半区直接调模型：不可行。客户端 bundle 禁止对 `@deepseek-ai/*` 做值导入，而且浏览器侧调用会把凭据路径搬进页面。

依赖任务自身的执行会话（Prompt 本来就会交给 agent）：不作为本 issue 的答案。报告者要的是任务存在之前就把表单填好。

从第一个已注册 provider 猜一条路由：否决。用哪个模型、花谁的额度，是部署决策而不是实现细节。

## Acceptance criteria

- 粘贴的一段内容能在当前项目里变成有标题、有描述的任务，不需要手工搬运。
- 未配置模型时，对话框用当前语言说明原因，并且不动已经输入的内容。
- 请求可以取消，不会把对话框卡住。

## Risks

粘贴内容里的提示注入可以左右草稿；用户会在创建前逐字段确认，且解析结果不会执行任何东西。带思考的模型可能超过超时。在没有维护者就「模型来源」做出决定之前，这个功能不做落地，因此该 issue 以设计方案回复后关闭，而不是一直挂着。
