# Agent Note: Release v0.3.13

Status: implemented
Archived: 2026-09-04

## Problem

The family needed its next unified release covering the `v0.3.12..dev` range: the phoebe-atelier skin batch (new radiant-strings-atelier skin with scene switching, artwork polish, halo/edge-decontamination fixes, LICENSE/NOTICE restoration, CSS scoping to the official shells, and the reviewed-hooks registry refresh), the remote-web-ui relay batch (quick-tunnel relay through a stable single-label dsh-market subdomain, the mandatory `/*` route pattern fix, origin Host stamping, and the new named-tunnel mode so paired phones survive restarts), the dsh-web-all subpath row display names, the dsh-perf removal of the deprecated better-session card and bsm core, the shared CSS module style-tag de-collision with the settings card contrast lift, and the center-column panel-mount core extraction shared by ssh and task-board.

## Decision

Release v0.3.13 (next patch after 0.3.12) by the standard unified-version flow, with no user-specified version so the default next-patch rule applied. The audit closed the range as safe for automatic upgrade:

- No persisted or wire identifier authored by this repository changed. The relay/named-tunnel features are additive (a new remote `tunnelToken` secret path plus a new market-worker relay registry and D1 migration 0007); the settings section ids, API paths, and storage keys are unchanged.
- The dsh-web-all subpath exports change is display-only: family rows still mount the same modules through `config.plugin`, and the marker manifest (`lib/shells/package.json`, no `dsh` field, type module) only steers the client scanner away from double-mounting.
- The better-session removal drops the dsh-perf Better Session card and bsm core (legacy-session migration surface); profiles that reference them lose that card, and stock jsonl keeps owning session storage.
- The CSS module style-tag id change (now the full repo-relative path instead of the basename) is bundle-internal; no persisted key or loader id depends on the old colliding names.
- The legacy aggregate dual-publish window stays closed: `@linxin666/dsh-web-ui-all` remains deprecated at 0.3.6 and the pipeline step is a no-op for 0.3.13.

Validation evidence: full gate set green (`typecheck`, `test`, `test:scripts`, `runtime-deps:check`, `aggregate --check`, `market:check`, `skin-center:check`, `docs:check`, `i18n:check`), all 19 family package versions bumped to 0.3.13, bundles and market assets rebuilt from the same bump and committed together, and the release pipeline (run 33698660992) succeeded end to end including the gated npm publish, the mount smoke, and the GitHub Release created from the committed bilingual notes. Post-release verification confirmed 0.3.13 on the registry for every publishable family package (including `@linxin666/dsh-client-ui-market`, which publishes under its client-ui name rather than its directory name) and the bilingual release body on the GitHub Release.

Branch handling was clean this time: `dev` carried the bump commit 823a334e (amended once to fold in the bilingual notes), `main` fast-forwarded from fc8896cc to 823a334e, the tag was cut from `main`, and `main` was merged back into `dev` so both branches sit at 823a334e.

## Alternatives considered

- Skipping the compatibility audit because every feature had shipped to dev days earlier: rejected — the audit is a release gate, not a merge gate, and the better-session card removal plus the style-tag id change both needed an explicit migration verdict (both classified as backward compatible with no persisted-identifier mapping required).
- A minor bump for the named-tunnel feature: rejected — the family's convention is a unified patch-per-release cadence and the feature is additive behind an opt-in secret.

## Consequences

- npm `@linxin666/*` moves to 0.3.13 across the family; the legacy `dsh-web-ui-all` stays deprecated at 0.3.6.
- `dev` and `main` both sit at 823a334e with no residual split.
- The named-tunnel mode and relay registry are live for users but the running DSH service still needs a user-side restart plus the market-worker deploy to pick up the new relay API surface; this release itself ships only the code.
- Release notes are the committed bilingual `docs/release-notes/v0.3.13.md` (Chinese default view, English fold); the pipeline used the committed file.
